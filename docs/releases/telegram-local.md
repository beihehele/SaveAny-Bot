# Telegram 文件保存发布说明

## v2.0.0-rc.13

修正 ShardReel 重试和取消的状态跟踪：保留原有有限次数及退避间隔，远端已受理的入库持续查询实际结果，临时查询失败不再耗尽操作重试预算。初始化、重试和完成响应统一处理终态；上传或完成请求与远端取消碰撞时，先回查回执，确认终态后再清理本地文件。

“跳过”仅保留已经入库的同名文件，不再把尚未完成的远端路径报告为已跳过。选择的跳过策略持久保存并传到远端接收入口，防止检查后出现的同名文件被另存一份。补齐远端名称的 512 字符限制及控制字符检查，保留 Bot 原有的整条路径长度限制。

本候选使用 ShardReel 当前存储 API 的重试能力和幂等回执，不新增配置、数据库迁移或历史兼容分支。最终发布身份、CI、NAS 升级和真实 Telegram 验收另记于本候选 GitHub Release；保持预发布，不更新稳定别名。

## v2.0.0-rc.12

网页“保存设置”支持新增、编辑和删除目录快捷方式及保存规则。默认目录只列当前所选存储的记录；编辑路径保留默认选择，删除默认目录或将它改到其他存储时恢复为根目录。目录操作只修改配置，不移动或删除已有文件。

规则提供常用文件类型、消息正则及媒体组/单条媒体匹配，可保存到指定存储或沿用本次选择；新增规则不会自动开启“应用规则”。编辑保留记录 ID；只修改保存目录时，原表达式保持不变，URL 正则不再被展示处理改写，配置凭据继续脱敏。上方偏好有未保存修改时，先保存再管理目录和规则。

ShardReel 目录配置复用实际后端的路径校验，在写入前拒绝过长路径和各级名称首尾空白；沿用本次存储的规则检查该用户可选择的后端。本地存储的有效路径保持原有规则。没有新增数据库表、配置项、历史兼容分支或媒体组处理流程。

本地全项目测试、vet、相关包竞态、Linux/amd64 构建及中英文/手机浏览器验收通过。发布身份、流水线、NAS 升级和真实 Telegram 验收结果另记于本候选的 GitHub Release。保持预发布，不更新稳定别名。

## v2.0.0-rc.11

减少一次链接提交中同一媒体组的重复查询，Bot 与 Web/API 共用提交内的取组结果。回归用例中，同组三个成员链接的取组请求由三次降为一次，文件选择及逐链接反馈保持原有规则。

只复用成功取得的成员，查询失败、空结果及此前未见的成员继续查询。复用按实际聊天、媒体组、成员和客户端隔离；`?single` 仍只选指定成员，每次新提交重新获取消息，未增加持久缓存、配置项或重试层。

本地全项目测试、vet，以及 API、Bot 链接入口和 Telegram 工具包竞态检查通过，包含保存、转发与取消回归。实际发布身份、NAS 升级和四成员链接验收结果记录在本候选的 GitHub Release；本节不代替线上验收。保持预发布，不更新稳定别名。

## v2.0.0-rc.10

## v2.0.0-rc.9

本候选新增可选的 ShardReel 存储：复用 Telegram 下载流程，完整落盘到持久化待上传目录后，由后台上传执行器调用 ShardReel HTTP API。最终成功通知和 hook 等待远端入库及大小、SHA-256 校验；成功后清理本地副本。失败重试、取消、重启恢复及清理状态保存在 SQLite，后台可查看、重试或放弃任务。

媒体组保存时，在选定目录内按有效 caption 建立子目录；清理非法路径字符和空白，最多 64 个字符且不超过 180 个 UTF-8 字节。相同有效 caption 的媒体组保存到同一目录，文件重名继续按原策略处理；空 caption 使用聊天和媒体组 ID 生成目录。该规则适用于 local 与 ShardReel，Telegram 聊天间转发行为保持不变。

SaveAny-Bot 面向个人使用：保存 Telegram 文件到本地或 ShardReel、监听新消息、复制聊天历史，以及可选的 admin 管理网页。监听与复制使用单来源到单目标模型。启用 ShardReel 不自动改变用户的默认存储。本版本仍为候选，不提升稳定标签。

## 当前功能

- 保存单文件、照片、视频和媒体组，按聊天/消息 ID 在一次链接提交中去重；`?single` 只选择指定成员。
- `/watch` 监听新消息，支持保存到默认存储或聊天/Topic 转发；`/copy` 按数量及过滤条件复制历史。
- 保留成员顺序、caption、富文本、来源链接及 Topic；可使用目录规则、命名模板和重名处理策略。
- Bot、网页和可选 API 共用任务队列、取消和生命周期 hooks。后台展示任务来源、近期结果、逐链接反馈和运行诊断。
- 网页提供控件内聊天搜索、管理中目标选择、默认不指定 Topic、radio 和字面关键词过滤。聊天/Topic 列表保存在 SQLite，只在点击“刷新列表”时同步 Telegram。
- 管理网页默认关闭，使用固定用户名 `admin` 和配置密码/密码哈希；认证独立于 Bearer API。
- ShardReel 提供持久上传任务、连接检查、远端目录浏览和文件下载；每个存储使用独立待上传目录和后台执行器。

配置、存储定义和 API 任务请求只接受当前文档定义的字段。存储类型为 `local` 和 `shardreel`；API 创建类型为 `tgfiles`。不提供旧版本配置或数据库索引迁移适配。使用当前配置示例和当前数据结构。

## 行为边界

任务接纳后，关闭网页不会取消执行；取消不会撤回已经确认发送的内容。复制扫描单页默认限时 5 分钟，可通过 `telegram.scan_timeout` 设置；扫描失败不发送部分选取结果。

媒体组取组采用有界查询。查询失败或为空会提示原消息回退，非空结果不证明任意跨度的整组完整。过滤按任一成员满足完整条件处理整组。

停止监听会清理该路由的等待内容，已接纳任务及已开始的转发继续完成；重建监听不继承先前缓冲。同目标聊天跨 Topic 的监听转发按接纳顺序串行，原始 ID 和 Topic 保持。

普通任务观察和审计保存在内存中，重启清空，不自动重放。ShardReel 上传任务独立持久化，重启恢复完整落盘文件；未完整下载的文件需重新下载。其成功、跳过和取消历史保留 7 天、最多 1000 条，失败及未完成任务不按年龄清理。文件执行与复制逻辑项分别计数；执行结束不等于所有项成功。Webhook 使用已捕获的终态和地址，不因历史淘汰改变发送决定。

ShardReel 成功后的本地清理失败会单独重试，不再次上传；失败文件保留至重试成功或主动放弃。取消不会删除已确认保存的远端文件，已发起请求的文件需确认远端状态后清理。空文件仍可保存到 local，ShardReel 后端明确拒绝空文件。

## 部署与恢复

部署使用固定版本或摘要；远端 Compose 需设置 `SAVEANY_IMAGE`。更新前停止同账号实例，备份配置、业务数据库、Bot/Userbot 会话及 ShardReel 待上传目录，保留对应镜像或程序。下载目录需要独立的媒体备份策略，状态备份不等于媒体备份。恢复时使用匹配的完整备份，不删除会话或混用版本排错。

Compose 显式挂载 `./shardreel:/app/data/shardreel`，容器重建时保留宿主机 `data` 和 `shardreel`。ShardReel 需开放存储 API、设置密钥并启用 Worker；有未完成任务时不要更换存储名称、URL、待上传路径或远端存储根目录。具体字段见当前存储配置文档。

Userbot 会话采用实际运行目录中的 `data/usersession.db` 或明确绝对路径。后台建议绑定本机或内网。同一 Bot/Userbot 账号只运行一套接收消息的实例。WSL 验收不替代最终 NAS/服务器上的目录权限、重启与恢复检查。
