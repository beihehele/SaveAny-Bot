# Telegram + Local 发布说明

本次发布聚焦 Telegram 实时监听、历史复制和文件本地保存，新增可选的管理员网页。属于兼容性变化，升级前必须按迁移说明检查配置。

- 保留 `/watch`、`/copy`、Topic、媒体组、过滤、caption、命名、目录与规则、取消和生命周期 hooks。
- 管理后台提供 `admin` 登录、任务与本地文件管理；默认关闭，可配置密码或密码哈希，与 Bearer API 认证独立。
- 删除网站解析与下载、Aria2、yt-dlp、远端存储、Telegram 再上传和自更新。API 创建任务仅支持 `tgfiles`，镜像不再包含 FFmpeg 等旧功能工具。
- 包含单文件/相册保存的自动回归，以及候选 Alpine 镜像内的队列、hooks、合成备份恢复和隔离重启验证。
- 后续候选修复：下载使用独占临时文件；统一 Bot/API/后台取消时的复制任务占用释放；查询返回有效的逐文件结果统计；清理无调用旧代码和部署说明。远端 Compose 现在必须设置 `SAVEANY_IMAGE`。
- Telegram 链接保存按聊天和消息 ID 在单次提交内去重，保留 `?single` 选择语义；HTTP 链接查询取消不会降级为部分文件保存，也不会取消共享客户端。保留 watch/copy 的成员选择、整组过滤、caption、富文本、来源链接与 Topic 契约；监听停止的接纳边界见下文。
- 修复保存、默认存储和配置按钮的成功回执，并限制回执及保存/复制进度消息的等待时长，完成时清理失效的取消按钮；连接恢复等待可被任务取消或服务关闭打断。`/copy` 每页扫描默认限时 5 分钟（含重连和限流等待），可用 `telegram.scan_timeout` 调整；超时不发送部分扫描结果。

- 后台统一展示 Bot/网页/API 任务来源与近期终态，Bot 记录最多 1000 条、24 小时；记录为进程内观察，重启不恢复任务。多链接输入反馈无效、失败与重复项，全失败不创建任务；选入不等于下载完成。
- 后台新增有界扫描页统计（history/search 的结果与耗时），不额外请求 Telegram；补同客户端连续超时后恢复的模拟回归，并删除未使用的任务字段与旧注释草稿。
- 网页/API 终态历史独立保留最多 1000 条、约 24 小时；仍在执行的取消任务保留到 worker 完成。Webhook 在记录淘汰后仍可按原规则发送/重试。此额度与 Bot 历史分开，不是后台总记录数或进程内存上限。
- 媒体组查询失败或空结果时保留原消息回退，并补充诊断日志；网页/API 的逐链接结果以可选 `album_fallback: true` 及中英文提示说明已知回退。选取状态与去重不变，非空查询结果不等于已经确认整组完整。
- `/unwatch` 成功后丢弃对应路由的待处理媒体组，旧回调和本地任务入队前再次核查路由身份；重建监听不继承旧缓冲。修复并发 `/watch` 可能重新写回已删除路由的问题。已经入队/执行中的保存任务及已经启动的转发继续原生命周期；停止监听不会截断已接纳的转发，也不代替任务取消。此保证适用于同一进程，保持同账号单实例。

Userbot 在建立媒体事件时即捕获接收路由，消抖、队列等待及 caption 刷新不会把旧事件重新分配给重建路由；其他存活路由仍正常处理。接纳时核查路由是否仍有效。此边界不按 Telegram 原发送时间截断重连补收消息，也不按监听建立时间拆分已选中的媒体组。

修复偏好更新保存关联快照的问题：修改静默、命名、默认保存等用户字段不会重新插入已删除的监听、目录或规则。关联项仍由对应管理方法处理，用户字段的 false/空值保存保持原样。

补齐 `/copy` 最后一次 RPC/进度以及空扫描最终反馈后的取消检查，保留取消原因、已确认复制数量和原 worker/hooks 路径；不撤回已发送内容、不自动重试，也不改变普通逐项失败累计后继续循环的策略。

`/copy` 执行后向后台历史提供固定大小的聚合结果，单条消息或一个媒体组各算一项。后台区分成功、普通失败、取消尝试、内部中断及未尝试数量，不将组数当作文件数。普通逐项失败仍沿用原完成状态及 hooks；计数不证明取组完整或来源归因编辑成功，也不触发自动重试。

监听转发改为独立有界调度：最多 4 个槽位、100 个等待项，同目标聊天跨 Topic 按接纳顺序串行；满队列拒绝并计数，不追加重试。停止路由会清理转发等待项，槽位通过最终路由校验后视为已开始，此后的转发不因停止而截断；本地保存任务的原生命周期保持。普通 ID/Bot API ID 保守共用调度键，传给转发的原 ID 不变。后台新增独立调度诊断，计数不证明整组完整，也不纳入任务历史或承诺源消息绝对顺序。

## 候选版本验收范围

`-rc` 版本作为候选包发布，不更新 Docker `latest` 或稳定主次版本别名，不设为 GitHub 最新正式版本。完整测试、竞态、vet、跨平台构建和容器检查由发布流水线再次执行。

真实 MTProto 登录、监听/复制、媒体组顺序与去重、Topic 和文件本地保存的验收记录，必须关联实际候选版本、镜像摘要和部署实例。使用可清理的私有测试聊天与合成文件，分别记录成功、取消和重试结果；自动模拟 RPC 回归不代表完成这些验收。本地监听需要先通过 `/storage` 设置默认 Local 存储。

包含停止监听补丁的候选包还须核对缓冲期间停止、其他路由继续、同来源/目标重建不继承旧成员，以及已接纳任务可继续完成。未提交源码构建的本地候选包使用明确的 dirty/源码指纹标识，不能算作已发布版本；rc.4 实测不代替后续候选验收。

## 升级与回滚

停止原实例，备份旧程序或镜像、配置、业务数据库、Bot/Userbot 会话和下载目录。在配置副本中仅启用 Local 存储，保留原 Local 名称及路径，核对默认目录、规则和路由，删除旧功能配置。迁移细则见仓库 `docs/content/zh/usage/migration.md` 或英文对应文档。

启用 Userbot 时，将会话放在实际运行目录下的 `data/usersession.db`，或使用明确的绝对路径；相对路径不以配置文件目录自动定位。首次验收使用独立数据目录和测试聊天，避免同时启动两个生产实例或触发已有监听路由。

候选镜像使用固定版本或摘要，不依赖 `latest`。配置检查或验收失败时停止候选实例，恢复匹配的旧程序/镜像与备份配置和数据；不要删除生产会话来排除错误。

## 2026-10-13 网页管理易用性

来源使用输入式单选下拉，直接搜索名称或聊天 ID；目标只列当前 Userbot 管理的频道/群，论坛目标按选择读取 Topic，默认不指定。聊天与 Topic 列表持久化到业务数据库，只有右侧“刷新列表”才同步 Telegram；扫描失败保留原缓存，创建复制/监听时仍实时检查目标权限。

新建任务通过页签选择保存或复制，切换保留草稿；处理方式和包含任意/全部关键词采用 radio。可选过滤按需展开并显示摘要，本地监听显示默认保存位置与设置入口，提交确认包含目标、Topic 和条件。任务列表显示现有结果计数，区分执行结束与全部成功。缓存采用独立新增表，升级前仍须完整备份；本次真实验收记录以发布版本及摘要为准。
