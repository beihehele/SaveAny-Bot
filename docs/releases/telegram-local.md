# Telegram + Local 发布说明

## v2.0.0-rc.8

本候选修复 Telegram 消息读取返回旧 caption/已删除组成员的问题，以及媒体组目录规则在单成员选择和单文件入口中的处理。保存表单提交期间锁定输入，响应未确认时保留链接并提示检查任务列表；Webhook 日志不再包含目标完整地址。

清除旧配置容忍、废弃 API 字段、旧监听索引修复及迁移说明，只支持当前配置、API 和数据结构。发布前本地测试、容器回归与真实 Telegram 照片/视频保存、监听、复制验收通过；正式发布产物与流水线结果另行记录。本版本仍为候选，不提升稳定标签。

SaveAny-Bot 面向个人使用：保存 Telegram 文件到本地、监听新消息、复制聊天历史，以及可选的 admin 管理网页。监听与复制使用单来源到单目标模型。

## 当前功能

- 保存单文件、照片、视频和媒体组，按聊天/消息 ID 在一次链接提交中去重；`?single` 只选择指定成员。
- `/watch` 监听新消息，支持本地保存或聊天/Topic 转发；`/copy` 按数量及过滤条件复制历史。
- 保留成员顺序、caption、富文本、来源链接及 Topic；可使用目录规则、命名模板和重名处理策略。
- Bot、网页和可选 API 共用任务队列、取消和生命周期 hooks。后台展示任务来源、近期结果、逐链接反馈和运行诊断。
- 网页提供控件内聊天搜索、管理中目标选择、默认不指定 Topic、radio 和字面关键词过滤。聊天/Topic 列表保存在 SQLite，只在点击“刷新列表”时同步 Telegram。
- 管理网页默认关闭，使用固定用户名 `admin` 和配置密码/密码哈希；认证独立于 Bearer API。

配置、存储定义和 API 任务请求只接受当前文档定义的字段。Local 是唯一存储类型；API 创建类型为 `tgfiles`。不提供旧版本配置或数据库索引迁移适配。使用当前配置示例和当前数据结构。

## 行为边界

任务接纳后，关闭网页不会取消执行；取消不会撤回已经确认发送的内容。复制扫描单页默认限时 5 分钟，可通过 `telegram.scan_timeout` 设置；扫描失败不发送部分选取结果。

媒体组取组采用有界查询。查询失败或为空会提示原消息回退，非空结果不证明任意跨度的整组完整。过滤按任一成员满足完整条件处理整组。

停止监听会清理该路由的等待内容，已接纳任务及已开始的转发继续完成；重建监听不继承先前缓冲。同目标聊天跨 Topic 的监听转发按接纳顺序串行，原始 ID 和 Topic 保持。

任务观察和审计保存在内存中，重启清空，不自动重放任务。文件执行与复制逻辑项分别计数；执行结束不等于所有项成功。Webhook 使用已捕获的终态和地址，不因历史淘汰改变发送决定。

## 候选发布验证

发布流水线执行测试、竞态、vet、Node 检查、SQLite 变体、支持平台构建、漏洞及容器检查。发布二进制为 Linux/amd64、Windows/amd64，容器为 Linux/amd64。

真实 Telegram 验收应关联代码提交、包/镜像摘要与部署实例。使用可清理的私有测试聊天及合成文件，核对本地哈希、媒体组成员/顺序、Topic、caption/实体、去重与取消；自动回归与真实验收分别记录，详见 `docs/reviews/README.md`。

未提交源码的本地镜像必须标明源码指纹，不作为已发布产物。`-rc` 候选不更新 Docker 稳定别名或 GitHub 最新正式版本。

## 部署与恢复

部署使用固定版本或摘要；远端 Compose 需设置 `SAVEANY_IMAGE`。更新前停止同账号实例，完整备份配置、业务数据库、Bot/Userbot 会话和下载目录，保留对应镜像或程序。恢复时使用匹配的完整备份，不删除会话或混用版本排错。

Userbot 会话采用实际运行目录中的 `data/usersession.db` 或明确绝对路径。后台建议绑定本机或内网。同一 Bot/Userbot 账号只运行一套接收消息的实例。WSL 验收不替代最终 NAS/服务器上的目录权限、重启与恢复检查。
