# 网页/API 任务历史预算与后续安排（2026-10-11）

本报告接续 [rc.4 实施与验收记录](2026-10-11-remaining-implementation.md)。起点为 dev `e3cdbd6`，本批改变网页/API 内存任务记录的保留策略；rc.4 标签、镜像和当前 WSL 实例仍对应运行代码 `237b53c`。本批本地验证不能算作已发布版本的 CI 或真实 Telegram 验收。

## 复核与实施

`api/progress.go` 原先只有约 24 小时终态保留期限，短期大量完成任务仍可累积记录。后台关闭 HTTP API 时也会通过同一个 factory/store 提交保存任务，因此预算同时适用于网页与 API。当前单用户没有已证实的内存故障，本批是独立的容量保护。

网页/API 共享独立的 1000 条终态额度；保留期限仍为约 24 小时。超限按最后更新时间从旧到新淘汰，相同时间按 ID 确定顺序。注册、终态转换、列表读取和原有周期清理会执行预算；排队及仍在执行的任务不被淘汰。正在执行的任务即使已经标记 cancelled，也要等 worker 完成最终结果与 hooks 后才能进入可淘汰历史。

Webhook 的目标地址在终态决策的锁内捕获，发送及重试不再依赖后续查找历史记录。一次通知决策、原有三次重试、服务停止取消和 90 秒通知期限保持原契约。已取消任务后来的有效最终统计继续补全 GET，不改终态、不再通知。

此额度独立于 Bot 队列观察的 1000 条额度；后台按 ID 合并，两者不是后台总行数上限。活动任务、尚未退出的执行线程和在途通知也不属于已结束历史预算；本批不宣称整个进程内存或队列容量已被限制。被淘汰任务详情返回原有的 404。

中英文后台提示及 API/后台文档同步解释上述范围。没有增加配置项、数据库迁移、任务回放或自动重试。

## 复核后推进：网页/API 媒体组降级反馈

再次核实后确认，原消息回退可能产生三种不同的选取结果：新增文件、被前面输入去重、不支持媒体。直接将降级统一改成 partial 会改变现有状态，并把重复项误述为部分成功。改为在每项 `input_results` 中增加可选 `album_fallback: true`，独立表示已知查询错误/空结果后的原消息回退；ready/duplicate/failed/partial、code 和新增文件数量沿用原计算。没有已知回退时省略字段，查询成功但返回一个成员也不按数量推断降级。

## 复核后推进：停止监听的接纳边界

本批明确 `/unwatch` 的契约：删除成功后丢弃该路由尚在等待的本地/转发媒体组；已经取出缓冲的回调、本地文件准备以及旧路由快照都须在接纳前核查身份。已入队或执行中的保存任务仍由任务取消入口管理；转发以启动 goroutine 为接纳边界，已接纳的整组转发可在停止回复之后继续完成。没有给共享 Userbot context 增加路由取消，也没有改变已开始转发的媒体组。

两种缓冲 key 均增加路由 ID，停止仅清理对应 ID 的定时器与成员；保留原定时器所有权检查、任一成员命中后整组处理、成员到达顺序、命名、Topic 与最终 RPC。单条媒体也在最终接纳时核查路由。删除数据库路由、插入缓冲、启动转发和批量队列接纳由一个短锁串行化；回调先释放缓冲锁，再进入接纳锁，文件准备和网络 RPC 均不在接纳锁内。身份使用数据库 ID、所属用户和创建时刻，没有新增永久墓碑表或数据库迁移。创建时刻按解码后的时间比较，避免旧 SQLite 驱动的字符串格式差异误判有效路由。

复核发现另一个相关问题：`User.WatchChat` 原先保存调用者快照中的全部路由，并发新增命令可能把刚删除的路由重新写回。现改为只插入本次新增路由，使用调用者的用户 ID；插入成功后才更新内存快照。旧路由、过滤和 Topic 不随新增命令重写。负对照已复现旧快照重建被删路由。

确定性回归覆盖按路由隔离、相同来源/目标/Topic/用户的不同路由身份、停止后旧定时器不能取走新缓冲、回调取出组后停止、过期快照、准备结束后的整组拒绝、删除/查询/接纳失败、取消、已运行转发无需等 RPC 返回即可停止监听，以及接纳和停止并发竞态。实际配置同步用户、SQLite 和应用队列在隔离子进程中核对删除权限、旧 ID 停止失败不影响重建路由及已入队任务继续保留；没有 Telegram 会话或外部请求。

三项 Go overlay 负对照只写入忽略目录：绕过有效路由检查、不清理对应缓冲、重新保存旧路由列表，均触发指定回归失败；正常源码通过。最初队列断言误将排队数理解为排队加执行中数量，修正为分别检查两者；失败日志保留，不算作产品缺陷。初次旧实现 overlay 先触发用户身份断言，调整夹具后才确认旧路由复活断言；原日志亦保留。WSL 辅助 shell 首次受 Windows 换行影响，执行检查前退出，修正换行后重跑；不把首次工具退出记作验证成功。

Windows 全量测试与 vet、监听/database/Userbot/core/copy/API/后台/queue 八包竞态已通过。WSL 最终冻结源码的十包回归、全量 vet、API/后台/database/监听四包 SQLite 变体及完整编译通过；API/后台/Userbot/监听四个测试二进制在独立、禁用外部网络的 Alpine 容器中通过。冻结清单显式包含三份新代码/测试文件，不只复制已跟踪文件。最终运行代码和测试与 WSL 快照一致，补录仅有两份 review 文档差异。
