## 发现并本地修复的发布问题

### ShardReel 多文件任务的 SQLite 锁冲突

实际四文件 ShardReel 保存任务在下载预约与后台上传并行时出现 `sqlite3: database is locked`。两张照片完成上传，后续文件未完成，整个任务正确显示失败；不能将本次 ShardReel 媒体组验收标为通过。

本地增加使用真实初始化流程、独立临时 SQLite 的并发事务回归，复现相同错误。修复是在业务数据库初始化时设置单连接池，让短数据库操作串行执行；不增加重试框架、不改下载/媒体组/上传协议，也不限制 Telegram 下载工作线程。检查现有事务回调均使用事务连接，避免单连接下重复获取连接。该选择面向当前单实例个人使用规模。

原因与 SQLite [读事务升级写事务的锁规则](https://www.sqlite.org/isolation.html) 一致；增加等待时间不能替代正确的并发事务安排。

### 后台拒绝 ShardReel 文件名中的冒号

同一真实大文件通过 ShardReel API 可以下载，但 NAS 上 rc.9 后台返回 `400 invalid_path`。后台将本地路径的冒号限制复用于远端逻辑路径。

本地修复仅将冒号检查保留在 local 路径处理中；远端仍拒绝目录穿越、UNC 和 NUL。回归测试先在旧实现上确认失败，再通过修复后的目录浏览和原始字节下载测试。

另在 NAS 私有临时目录运行隔离校验程序，使用本地修复后的真实后台路由和独立配置、数据库完整回读上述真实大文件。HTTP 200、长度和 SHA-256 均一致；未启动第二个 Bot，未替换线上程序。
