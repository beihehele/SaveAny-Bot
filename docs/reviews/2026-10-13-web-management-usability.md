# Web 管理：单来源、单目标与持久列表缓存

复制和监听采用 1→1 模型。来源为输入式单选下拉，按名称或聊天 ID 筛选；编辑文字立即清除旧来源 ID，未选定聊天时阻止提交。支持鼠标、键盘方向键/回车及 Esc，输入法组合期间不确认，触摸滚动不选中。

来源、目标和 Topic 控件右侧提供“刷新列表”。来源和目标共用聊天快照，Topic 按目标分别保存。页面加载、浏览器重新加载和目标切换只读取业务 SQLite 中的快照，没有自动 Telegram 同步；首次缺少缓存时明确提示手动刷新。缓存按当前 Userbot 登录账号隔离，只存展示 ID、标题、管理/论坛标志及时间，不存 access hash 或登录凭据。Userbot 身份尚未初始化时不猜测旧缓存归属。

显式同步在服务内串行执行；聊天遍历普通/归档对话，最多 100 页/10000 项，Topic 最多 1000 项，仍受 25 秒请求预算约束。完整扫描成功后原子替换快照，失败/取消/超限保持旧缓存；聊天同步同事务清除已失去管理身份或论坛能力的目标 Topic 缓存。缓存跨数据库重新打开保留。新增缓存表不改变监听身份或用户同步逻辑。

目标仅展示管理中的频道/群，源目标不能相同。数据库缓存不替代创建前的实时访问、管理身份和 Topic 校验。本地保存只显示来源、过滤条件；隐藏目标和 Topic。普通聊天隐藏 Topic；论坛目标加载本地 Topic 列表，第一项和默认项“不指定 Topic”。目标切换清空旧选择并拒绝过时响应，刷新同一目标保留仍有效的 Topic，失败保留现有列表和选择。

处理方式与包含任意/全部关键词方式使用原生 radio。字面关键词、排除词和样本文字测试沿用原过滤解析器的 16 词/256 UTF-8 字节预算及媒体组任一成员匹配整组的规则。复制沿用原单来源任务、占用、取消和结果历史；未确认提交不自动重试。多来源弹窗、批量复制接口及父子任务编排已移除。

验证：全项目 Go 测试/vet、admin/database/handlers 的 race 回归、SQLite 变体、静态构建和 Node/脚本检查通过。数据库测试验证重新打开后的快照、取消保护、账号隔离及过时 Topic 清理；HTTP 测试验证普通读接口零 RPC、完整归档扫描、失败不覆盖、同步互斥及陈旧管理身份不能绕过复制校验。隔离浏览器验证首次缺缓存提示、三个刷新入口、刷新网页读缓存、失败恢复、Topic 保留、radio 请求、本地模式隐藏及中英文/手机宽度。

改动保留本地，尚未提交或部署；模拟页面与单元测试不替代本轮真实 Telegram 同步验收。现有 WSL rc.5 的验收记录对应已部署版本，不覆盖这些新增代码。

上述状态为提交前快照。发布准备阶段已将内部分页游标改为类型化结构，清理闲置翻译键和重复过滤样式；新增循环/扫描预算耗尽时保留旧快照的回归。候选发布及真实验收状态另以 review 索引关联的发布报告为准。

## 产品经理与 UI 视角复核

今天的功能方向适合单人管理：单选来源、管理中目标和按目标加载的 Topic 构成清晰的 1→1 流程。显式同步与数据库缓存让列表更新可控，radio 让互斥选择一眼可见。主要问题来自信息层级及结果反馈，已做以下完善：

| 问题 | 已实施调整 |
| --- | --- |
| 本地保存与历史复制同时铺开，复制入口被推到长页面下方 | 新建任务用页签先选择目的，切换保留草稿；支持方向键、Home/End 与正确的 aria-selected/tabpanel 关系。 |
| 可选过滤及样本测试占据主要操作区域 | 默认收起过滤，摘要显示实际包含/排除词及任意/全部方式；样本测试另按需展开。非法条件自动展开、持久提示并定位输入。 |
| 本地监听隐藏目标后看不出保存位置 | 展示当前默认存储、目录、保存规则提醒和设置链接；缺少默认存储时主动提示并阻止提交，修正设置后提示恢复。目录相对于存储根目录，规则可能覆盖默认落点。 |
| 确认框信息不足，隐藏条件容易误用 | 确认框包含来源、目标、Topic、关键词和复制数量；本地监听还列出默认存储/目录及适用的规则提醒。 |
| 流程完成被误读为全部成功 | 已知计数未全部成功的完成任务，以及未全部确认成功的完成复制，显示中性的“执行结束”；复制失败/部分结果标红。列表展示现有成功、失败及非零取消/中断/未尝试计数，并区分消息/媒体组与文件单位。文件详情将 JSON 改为可读计数，未保存包含失败和跳过。 |
| 测试文字或条件修改后旧结果仍可能显示 | 编辑清除旧结果；迟到的成功或错误响应都须对应当前文字和条件才显示。 |

文案简化了“逻辑项”“接纳边界”等主流程术语，技术限制与媒体组匹配规则仍可在展开过滤说明及任务详情中查看。提交继续复用单来源服务；界面状态标签仅解释已有结果，后端执行状态和 hooks 契约保持原状。

本轮追加验证：Node 语法及三项筛选编译测试、admin Go 回归及 vet 通过；隔离浏览器检查页签输入保留、键盘切换、过滤摘要去重、收起条件的错误定位、确认内容、实际单来源复制请求、默认存储缺失阻止提交与恢复、规则/目录摘要、过时样本错误丢弃、任务结果及详情。中文桌面及英文 390px 手机布局检查通过，无页面横向溢出。交互中的聊天/Topic 请求仍为数据库读取，显式刷新以外没有列表同步请求。目录和聊天标题中的 HTML 按纯文本展示。

下一步应以真实账号验收聊天与 Topic 同步、权限变化及实际复制/监听操作；保留简单模型，依据使用反馈决定是否需要监听编辑或目录/规则网页管理。本轮模拟数据验证不证明 Telegram 权限、列表规模或真实发送行为已经验收。

发布后续：上述本地状态为历史快照。实际 rc.6 镜像网页验收发现脚本白名单遗漏，已修复并增加 HTTP 入口回归，以 rc.7 重新发布。聊天/Topic 同步、缓存重启持久化、真实网页复制/监听表单及照片/视频保存转发验收通过，详见 [rc.7 发布与验收报告](2026-10-13-rc7-release-acceptance.md)；真实权限撤销场景仍未制造和验收。
