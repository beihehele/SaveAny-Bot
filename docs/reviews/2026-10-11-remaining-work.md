### 最终服务器迁移门槛

1. 确认架构、Docker/Compose、磁盘、目录权限、持久卷和备份位置；核实 Telegram、镜像仓库及代理的实际可达性。当前局域网代理不能假定在服务器可用。
2. 明确候选与回退版本及镜像 digest。停止源实例写入后完整备份配置、业务 SQLite、Bot/Userbot 会话及本地文件，收齐实际配置涉及的所有持久路径；保护旧备份并校验恢复。
3. 确认后台访问范围和管理员秘密。需要远程访问时验证 HTTPS、Host、同源/CSRF 与 `secure_cookie` 契约；不借用 API Token 代替后台登录。
4. 保持同一 Bot/Userbot 单实例：服务器接收消息前停 WSL；回退时先停服务器，再恢复旧版本与完整旧备份。不能用已迁移的新库冒充旧版恢复验证。
5. 核对版本、健康检查、后台登录、存储挂载和队列；用允许清理的测试内容完成保存、媒体组、copy/watch/topic、取消和停机退出验证，记录数量、哈希/内容、顺序及终态。
6. 验证目标或等价环境的备份恢复和旧版本回退。已有合成恢复回归和 WSL 升级备份不等于最终服务器回退验收。

WSL 临时保活及 Windows 登录自动启动不作为最终服务器方案；既然计划迁移，不为本机另加一套长期启动机制。
