# Web administration

The optional console uses the fixed username `admin`. It is disabled by default and independent of the Bearer-token API.

```toml
[admin]
enable = true
host = "127.0.0.1"
port = 8081
password = "replace-with-your-long-password"
session_ttl = "12h"
secure_cookie = false
```

Passwords must contain 12–1024 bytes. Restart manually and visit `http://127.0.0.1:8081/admin/`. The console starts after Telegram initialization; use container logs for earlier startup failures. Invalid console credentials or listener settings prevent the console from starting without stopping the Bot; a configuration decoding error still prevents application initialization.

Prefer a hash: run `saveany-bot admin-password`, enter and confirm the password, and replace `password` with the printed `password_hash` line. Only the bounded Argon2id format generated by this command is supported. The command does not start the Bot or read configuration. Secret-file automation can use `saveany-bot admin-password --stdin < /path/to/password-file`; it removes one trailing newline and preserves spaces. Do not put passwords in command-line arguments.

The Docker default entrypoint starts the Bot and does not forward CLI arguments. To generate a hash, use `docker run --rm -it --entrypoint /app/saveany-bot <your-image> admin-password`, or execute `/app/saveany-bot admin-password` inside a running container.

All fields support `SAVEANY_ADMIN_*` environment variables, including `SAVEANY_ADMIN_PASSWORD_HASH`. Exactly one of `password` and `password_hash` is required. Session lifetime must be between `5m` and `24h`, defaulting to `12h`.

The repository Compose uses host networking. For a custom bridge network, listen on `0.0.0.0` inside the container and publish to host loopback, such as `127.0.0.1:8081:8081`. For LAN use, configure the listener explicitly and use an HTTPS reverse proxy with `secure_cookie=true` and the original Host preserved. Arbitrary forwarded headers are not trusted. HTTPS-only cookies cannot maintain an HTTP login. Existing API tokens cannot log into the console, and console cookies cannot authenticate the original API. Deploy a fixed version or image digest containing the console and verify the running commit. The `latest` tag changes with releases and does not confirm that a feature has been updated.

The console provides overview, active queue tasks, tracked web/API results, task submission/cancellation, storage capabilities, local directory browsing and Range downloads. Watch routes and save preferences are read-only and do not alter media-group processing. Forwarding outside the queue is not represented as a cancellable task.

Recent terminal observations cover Bot, web and API queue tasks, with submission sources and available progress/counts. Records are in memory and reset at restart. Web/API history retains up to 1000 terminal entries for about 24 hours, evicting the least recently updated first; Bot queue observations have an independent 1000-entry, 24-hour budget. The console merges them by ID, so these budgets are not a total row limit. Queued, executing and cancellation-cleanup tasks are not evicted by history limits. Existing completion and hook decisions remain unchanged; unavailable copy counts are not fabricated. Diagnostics also show watch backlog/drop counters, local available disk space and Telegram initialization. Initialized is not a live connectivity check; watch counters reset at startup and are not file outcomes. Diagnostics use a configuration whitelist and up to 100 in-memory management operations, not arbitrary log/config files. Known configuration/database/session files and sidecars are protected from downloads, including aliases. Keep private deployment files and other deployment files outside local save roots: administrators may access other files inside those roots.

Sessions are bounded to 16; new sessions evict the earliest-expiring entry when necessary. Logout and restart invalidate sessions. Each client address can make five login attempts per minute; clients behind a reverse proxy may share that quota. Browser writes require same-origin Origin and a session-bound CSRF token. Cookies are HttpOnly/SameSite=Strict; the browser stores only language preferences outside cookies.

Chinese/English UI assets are embedded in the Go binary. No CDN, Node runtime, or additional frontend container is required.

Task details show link selection results by submitted position. Creation shows a separate dialog for failed or duplicate inputs, known album fallback or omitted metadata. Album lookup errors and empty results indicate that only the original message was considered; the warning remains when that message is already selected or unsupported, preserving existing ready/duplicate/failed statuses. All-failed requests retain the input and do not create a task. At most the first 100 results are shown, with an omitted count. Selection means inclusion in a task, not download completion or proof of a complete album. The Bot sends a separate bounded note for failed, duplicate or partly selected links, preserving the original selection keyboard and captions; Bot positions refer to matched Telegram links and each note shows at most ten entries.

Scan diagnostics report completed history/search pages, successes, failures, timeout/cancellation subsets, and last/maximum page durations since startup. They retain no per-request content and measure pages rather than whole tasks.
