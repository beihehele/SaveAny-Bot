# Telegram 精简版本迁移

本版本只保留 Telegram 监听/历史复制、Telegram 文件本地保存及管理后台。更新前停止实例并备份程序/镜像版本、配置、业务数据库、Bot/Userbot 会话和下载目录；本程序不自动删除已有文件或改写失效存储引用。

## 配置与数据检查

- 只启用 `type="local"` 的存储，保留原有本地存储名称和 `base_path`。
- 用户允许列表、默认存储、目录记录和规则应引用已启用的本地存储；`CHOSEN` 规则保留选择当前存储的含义。
- 移除 Aria2、yt-dlp、解析器设置和旧远端后端配置。启用的旧功能或后端会被拒绝；禁用的旧 Aria2/解析器/存储块可暂时被忽略，但建议从配置中删除。`[ytdlp]` 会明确报错。
- 旧 `no_clean_cache` 配置可删除，`--no-clean-cache` 参数已删除；退出仍不会清空整个缓存目录。
- 默认目录和规则中的失效名称会被报告，不会自动迁移到另一个目标。需要保留同名 Local 配置或在备份副本中修正后再更新。

## 接口与部署变化

删除 Bot 命令 `/dl`、`/aria2dl`、`/ytdlp`、`/parser`、`/transfer`、`/update`，以及 CLI `upload`、`watch`、`upgrade`。Telegram `/watch`、`/copy` 保留。API 创建类型只支持 `tgfiles`，`path` 为目录，单文件和媒体组均拼接各自文件名。其他任务类型会被拒绝。

镜像不包含 FFmpeg、ffprobe 或 yt-dlp。普通 Telegram 转发和本地下载无需这些工具；本版本不提供再次上传 Telegram 的存储后端。

先在隔离目录构建及验证候选镜像，然后人工切换已验证版本。配置检查失败时保留原数据并恢复旧程序/镜像和对应配置；不要将旧版本配置直接覆盖已调整的配置而丢失迁移记录。

## 验收

核对旧目录/规则/路由、单文件与相册本地保存、`/watch` 转发及 Topic、`/copy` 和取消，再检查后台登录、文件下载以及重启后的数据持久化。真实 Telegram 媒体组联调需要独立账号和聊天；未具备环境时保持待验收状态。
