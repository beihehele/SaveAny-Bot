# 复制历史消息

{{< hint warning >}}
该功能需开启 UserBot 集成.
{{< /hint >}}

将源频道/群的历史消息按条件筛选后，经 UserBot **无来源复制**（`DropAuthor`）到目标聊天（可指定论坛话题），并在消息开头加上可点击的 `[转]` 链接。源消息删除不影响已复制内容。不下载、不落本地存储。

## 用法

```
/copy <source_id> <target_id[:topicId]> [filter] [count]
```

| 参数 | 说明 |
|---|---|
| `source_id` | 源聊天 ID 或用户名（必填） |
| `target_id[:topicId]` | 目标聊天（必填）；不支持 `0`；`:topicId` 为论坛话题 ID（见 `/lstopic`） |
| `filter` | 可选，`msgre:<布尔表达式>`；省略则按时间从新到旧取消息 |
| `count` | 可选，命中条数，默认 500，最大 5000；从新到旧凑够为止 |

### `msgre` 表达式

前缀 `msgre:`，冒号后为关键词布尔表达式（**不是正则**）：

| 符号 | 含义 |
|---|---|
| `&` | 与 |
| `|` | 或 |
| `!` | 非（紧跟一个词） |
| `()` | 分组 |

匹配不区分大小写（子串包含）。示例：

```
msgre:plana&(planb|planc|pland)
msgre:plana|planb|planc|pland
msgre:plana&vip&(!spam)
```

示例:

```
/copy -1002229835658 -1003333444555
/copy -1002229835658 -1003333444555:12345 msgre:plana|planb
/copy -1002229835658 -1003333444555 msgre:plana&(planb|planc) 100
/copy -1002229835658 -1003333444555 50
```

## 行为说明

- 扫描使用 Telegram 服务端搜索（有关键词时）或历史分页（无 filter）
- 进度分两阶段：扫描 → 发送，可点取消按钮或用 `/cancel` 停止
- 进度消息编辑最多等待 5 秒；更新失败不会阻塞复制。取消后的终态反馈也有独立的 5 秒时限。
- 扫描及发送的最后一次反馈后也检查取消，避免最后一条已结束却漏掉取消状态。已经确认复制的内容与计数保留，不撤回或自动重试。
- 同一用户同时只能有一个进行中的 `/copy` 任务
- 每页扫描默认最多等待 5 分钟（含断线恢复及 `FLOOD_WAIT`）。通过 `[telegram] scan_timeout = "10m"` 或 `SAVEANY_TELEGRAM_SCAN_TIMEOUT=10m` 调整；超时明确失败，不发送部分扫描结果，也不会取消共享 Userbot 客户端。
- 命中后 `forwardMessages`（DropAuthor）；相册整组转发，再编辑 caption 在开头加上可点击 `[转]`
- `count` 按命中条数计（相册整组算 1 次命中）
- 普通逐项转发失败会累计到 Bot 的成功/失败回执，循环仍会继续；后台的完成状态不等于所有项成功。执行结束后历史保留聚合计数，单条消息或一个媒体组各算一个逻辑项；取消后尚未尝试的项保持 pending，取消尝试/内部中断仍计入 Bot 回执的失败数。成功调用不证明整组完整或尽力而为的来源链接编辑成功。扫描失败不发布部分选取数量，请求 count 也不等于实际选中总数。
- 由 **UserBot 个人账号** 执行；原文字样式随转发保留

## 与 /watch 的区别

| | `/watch` | `/copy` |
|---|---|---|
| 时机 | 实时监听新消息 | 回溯历史消息 |
| 目标 `0` | 可保存到默认存储 | 不支持 |
| 输出 | 本地存储或 DropAuthor 复制 | 仅 DropAuthor 复制 |

媒体组取回使用代表消息前后各最多 49 个 ID（总计最多 99 个），单个正常 peer 查询在原 100-ID 分块预算内；可覆盖窗口内稀疏、交错成员，按 ID 排序去重，不混入其他 group。取消、超时或 FLOOD_WAIT 不继续尝试 peer 别名。查询结果仍是有限窗口中的尽力选取，无法知道预期成员总数；非空、一成员或超过窗口的情况不自动标为已知降级，也不证明整组完整。

扫描按服务端原始页长度及游标分页，置顶等服务消息不会被复制，也不会使满页提前结束。异常重复或不推进的游标会使扫描失败，不转发部分扫描列表。
