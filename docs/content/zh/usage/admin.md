# 网页管理后台

后台默认关闭，启用后使用固定账号 `admin` 登录。它是本实例管理员入口，与 HTTP API 的 Bearer Token 相互独立，不需要同时启用 API。

## 启用与登录

在配置文件加入：

```toml
[admin]
enable = true
host = "127.0.0.1"
port = 8081
password = "replace-with-your-long-password"
session_ttl = "12h"
secure_cookie = false
```

密码需为 12–1024 字节，没有默认密码。保存配置后人工重启，打开 `http://127.0.0.1:8081/admin/`。后台在 Bot 初始化后启动；Telegram 登录前的错误仍查看容器日志。后台的凭据、端口等验证失败会拒绝启动后台，Bot 继续运行；不能解析的配置文件仍会使应用初始化失败。

建议使用哈希代替配置中的明文密码：

```sh
saveany-bot admin-password
```

Docker 镜像的默认入口启动 Bot，不转发 CLI 参数。生成哈希时使用 `docker run --rm -it --entrypoint /app/saveany-bot <你的镜像> admin-password`，或在运行中的容器内执行 `/app/saveany-bot admin-password`。

此命令不启动 Bot，也不读取部署配置。在终端输入并确认密码，将输出的 `password_hash = "..."` 放到 `[admin]` 中并删除 `password`。仅接受此命令生成的有界 Argon2id 格式。若通过秘密文件自动化设置，可用 `saveany-bot admin-password --stdin < /path/to/password-file`；命令只去掉末尾一个换行，保留密码中的空格，不要将密码写进命令行参数或 shell 历史。

支持 `SAVEANY_ADMIN_ENABLE`、`SAVEANY_ADMIN_HOST`、`SAVEANY_ADMIN_PORT`、`SAVEANY_ADMIN_PASSWORD`、`SAVEANY_ADMIN_PASSWORD_HASH`、`SAVEANY_ADMIN_SESSION_TTL`、`SAVEANY_ADMIN_SECURE_COOKIE` 环境变量。`password` 与 `password_hash` 必须且只能设置一个；有效期支持 `5m` 至 `24h`，默认 `12h`。

## Docker 与内网访问

项目默认 Compose 使用 host 网络，`127.0.0.1` 监听适用于宿主机本地访问。若自建 bridge 网络 Compose，需让容器内监听 `0.0.0.0` 并发布端口到宿主机 `127.0.0.1:8081:8081`。不要仅修改容器内监听地址就认为端口已经发布。

如需局域网访问，显式配置监听范围，并通过 HTTPS 反向代理访问，设置 `secure_cookie=true`。代理必须保留原始 Host，不跨域代理管理接口；后台不信任任意 `X-Forwarded-*` 请求头。`secure_cookie=true` 后使用 HTTP 将无法维持登录。原 API Token 不会授予后台访问权，后台 Cookie 也不能替代 API Token。

部署时使用包含后台改动的固定版本或镜像 digest，并核对运行中的提交号。`latest` 会随发布变化，不能只凭标签确认新功能已更新。

## 功能与数据范围

总览和任务页在有活动任务时每次加载完成约 3 秒后刷新，空闲时约 15 秒；搜索、筛选和分页不影响活动任务判断。后台标签页、打开的任务详情和正在操作的表格控件会暂停自动刷新，仍可手动刷新。

- 总览：版本、提交、后台运行时长、队列及已加载存储。启用 ShardReel 时还显示待完成文件数、失败文件数和暂存额度占用；占用包含下载预留及尚未清理的文件，不是实时目录大小。任务能力只检查本地前置条件，不保证远端可用。
- 任务：队列中 Bot/API 活动任务，以及 Bot/网页/API 任务的近期终态结果和已有进度。搜索、筛选、分页和取消；取消中的任务需等到 worker 释放后才完成。监听转发采用独立调度，不在本任务列表中；其状态计数在诊断查看。
- 新建任务：输入 Telegram 消息链接并选择本地、ShardReel 或 TG收藏 保存位置；另有历史复制向导，选择一个来源、一个管理中的目标聊天及可选 Topic，复制数量为 1–5000 个消息/媒体组逻辑项。复制不支持目标 0，与 Bot 共用每用户复制占用、队列、取消和结果历史；不会向 Telegram 发送网页进度消息。接纳后关闭页面不会取消任务。不提供任意命令或 webhook 表单。
- 存储/文件浏览：能力查询，本地目录分页浏览与附件下载（支持 Range），以及 ShardReel 目录浏览、下载和连接检查。不提供文件修改；已知配置、业务库、Bot/UserBot session 库及 sidecar 不能下载，即使通过文件别名访问。管理员可以访问本地存储根目录内其他文件，因此应将保存目录与私有部署文件分开。
- 监听路由：选择配置用户后创建或停止路由，选择“保存到存储”或一个管理中的目标聊天，每次提交创建一条来源到目标的监听。Topic 随目标自动加载，首项且默认项为“不指定 Topic”。监听仅处理照片、视频、文件，纯文字不处理。复用 Bot 的聊天解析、Topic 和过滤验证及停止门禁。修改路由请停止后新建，旧事件不会绑定到新路由；停止丢弃未开始项，已开始的转发及已接纳文件保存可能继续完成。
- 保存偏好：只提交明确修改的静默、默认存储/目录、应用规则、命名和冲突字段，保留并发操作中未修改的字段。同页支持新增、编辑、删除目录快捷方式及保存规则。默认目录只列所选存储的记录；删除当前默认目录或将其改到其他存储后恢复为根目录，保留默认存储。目录操作不移动、删除已有文件，实际目录由后续文件保存创建。规则提供常用文件类型、消息正则及媒体组/单条媒体匹配，目标可选具体存储或沿用本次保存的存储；新增规则不会自动开启“应用规则”。编辑保留记录 ID，已有文件不重新整理。上方偏好有未保存修改时需先保存，避免管理列表刷新丢失输入。过滤/命名预览使用合成样本，不读取 Telegram 或保存偏好；模板预览限普通文本及文档字段，不执行循环或格式化函数。后台不创建/删除 Telegram 用户。
- 诊断：白名单运行配置、监听入口积压及丢弃、转发调度容量/占用/结果及拒绝计数、本地磁盘可用空间、history/search 扫描页次数与耗时、超时/取消计数、Telegram 初始化状态和最多 100 条管理操作。初始化状态不等于实时网络连通，监听计数自启动累计且不代表文件执行结果。不提供任意日志文件读取，不返回密码、token、session 或完整部署配置。

来源使用可搜索的单选下拉控件，直接在控件输入框内按名称或聊天 ID 筛选。来源和目标共用本地数据库中的聊天列表，包含普通及归档聊天；点击任一右侧“刷新列表”会完整同步后替换这份缓存。目标下拉框只列当前 Userbot 账号为创建者或管理员的频道/群，并阻止来源与目标相同。管理员身份不保证实际发送权限；创建时重新核对管理身份，后续 Telegram 权限变化仍可能使任务失败。

默认使用关键词编辑：每行一个词或短语，通过 radio 选择包含任意/全部关键词，另填排除词；监听的文件保存/聊天转发也使用 radio。匹配消息文字/媒体说明，不匹配文件名，不把符号当作正则表达式。遵守现有 16 个词、256 UTF-8 字节限制；英文双引号暂不能作为基本关键词。媒体组任一成员满足完整条件时处理整组，排除词按该成员判断，而非整组否决。样本文字测试不读取或发送 Telegram 消息。Topic 默认不指定，切换目标会清空旧选择，旧请求不能覆盖新列表。

新建任务先通过页签选择“保存文件”或“复制聊天历史”；页签切换保留已填写内容。可选过滤默认收起，摘要显示实际包含/排除词；填写错误会展开提示。展开后可测试样本文字，修改条件或样本会清除旧结果。保存监听显示当前默认存储、目录和保存规则提醒，可跳转到保存设置；未设置默认存储时不能创建保存监听。

提交前确认来源、目标、Topic、过滤条件和复制数量；保存监听还显示默认保存位置。复制作为一个可取消任务运行，网页关闭后已接纳任务继续执行；监听每次创建一条路由。网络或服务端错误可能意味着已接纳但未确认，需先检查任务/监听列表，不自动重试发送。聊天列表加载失败和提交拒绝保留当前表单；刷新浏览器会重新加载页面，未提交的配置需重新填写。

任务列表直接展示可用结果计数，并区分消息/媒体组与文件单位。完成任务的已知结果未全部成功时显示“执行结束”；复制完成但没有成功确认时也使用此标签，实际结果仍需查看成功、失败、取消、中断和未尝试数量。文件“未保存”包含失败及按重名策略跳过的文件；详情提供各项计数。执行状态与 Bot 完成/hooks 契约保持一致，界面不补造缺失计数。

普通队列任务记录和审计在内存中，重启清空。ShardReel 上传任务保存在 SQLite，展示逐文件进度和清理状态，重启后恢复已完整暂存的文件。已清理终态上传历史保留 7 天、最多 1000 条；失败、未完成和未清理任务保留。网页/API 共享最多 1000 条终态历史、最长约 24 小时，超限先清理最早更新的记录；Bot 队列观察另有独立的 1000 条、24 小时额度，后台按 ID 合并，两类额度不是后台总行数上限。排队、执行中及取消收尾的任务不因历史额度被淘汰。记录提交来源；现有文件结果统计仍遵循原完成/hooks 契约，复制任务执行后按单条消息/整组逻辑项提供有界汇总，不把它当文件数；旧记录不补造计数，普通失败的状态/hooks 政策不变。会话最多 16 个，新增会话超限会淘汰最早到期的会话；退出或服务重启使旧会话失效。单个客户端地址每分钟最多 5 次登录尝试，代理后的客户端可能共享该额度。

中英文界面资源随二进制内嵌，无需 CDN、Node 运行环境或额外前端容器。浏览器只保存语言偏好，登录 Cookie 为 HttpOnly；写操作校验同源 Origin 和会话绑定的 CSRF token。

链接选取结果在任务详情中按提交序号展示；存在失败、重复、已知媒体组降级或未展示项时，新建任务后也会弹出提示。整组查询失败或空结果时会标明仅尝试选取原消息；即使原消息已被前面的链接选入或无法保存，该提示仍保留，原有选入/重复/失败状态不变。全部失败时保留输入并说明各项原因，不创建任务。最多展示前 100 项并提示未展示数量；选入只表示加入任务，不代表下载完成或媒体组完整。Bot 消息中的失败、重复或部分选入项会通过独立提示消息反馈，不修改原选择键盘与媒体描述；Bot 序号对应识别到的 Telegram 链接，单次提示最多列出 10 条。

监听转发诊断仅统计该调度器：工作槽位包含最终路由校验，拒绝和丢弃不会自动重试，成功不证明取组完整或归因编辑成功。转发最多 4 个槽位、100 个等待项；按同目标聊天的接纳顺序串行，原 ID 与 Topic 保持不变。详情及停止边界见 `/watch` 文档；前置媒体缓冲和本地保存/复制不属于此容量额度。

管理操作均需登录、同源请求及 CSRF token；仅接受配置中的用户。来源访问、Topic 查询、列表同步和创建准备最多同时两项，单次 25 秒，不自动重复提交。创建/停止监听、复制、偏好修改、目录/规则增删改和预览记录有界审计；失败详情记录服务端日志，页面不直接返回原始 RPC 错误。Topic 分页拒绝游标循环并有固定页数预算。普通任务持久历史和重启回放不属于本次网页能力。

复制流程终态使用 worker 的明确结果并执行对应 hooks，后台另显示全部成功、部分失败/中断、全部未成功或无命中，避免将“已完成”当作全部转发成功。不会重试已发送内容。

中断计数意味着没有取得成功确认，发送可能已在服务端完成，不能据此自动重试。重选当前存储名不会清默认目录；真正切换存储时清旧目录，或同时明确选择新目录。

偏好写入在事务内核对最终的静默、存储和目录组合。并发操作不会保存不匹配的存储/目录；校验失败时整次修改回滚。重选相同存储保留目录，切换存储清空旧目录，或同时明确选择属于当前用户及新存储的目录。

页面加载、浏览器刷新和目标切换只读取本地数据库，不自动请求 Telegram。首次无缓存时提示点击右侧“刷新列表”；列表显示上次同步时间。缓存按 Userbot 账号隔离，Topic 按目标聊天单独保存，只包含 ID、标题及展示状态，不保存 token/session/access hash。完整同步成功后原子替换，失败保留原缓存和选择；聊天同步也清理失去管理身份或论坛能力的目标 Topic 缓存。缓存不代替提交时的实时访问、管理身份及 Topic 校验。列表同步串行执行；聊天最多 100 页/10000 项，Topic 最多 1000 项，超限或超时保留旧缓存。数据库重启后仍保留列表，迁移只新增缓存表。文件保存隐藏目标及 Topic，仅论坛目标显示 Topic；Topic 默认不指定，刷新同一目标时尽量保留仍有效的选择。

### 任务取消与记录删除

任务行只显示“详情＋取消”或“详情＋删除”，两者均直接执行，不弹二次确认。排队、下载、上传和等待自动重试均属于进行中；取消收尾时按钮禁用，任务彻底结束后可删除。取消不会撤销已保存文件或已发送消息。

删除仅清理任务历史、关联文件明细和待重试上传的临时数据，不删除已保存的本地/ShardReel 文件，也不撤回 Telegram 消息或修改监听。ShardReel 删除先停止重试，确认远端取消或完成，清理临时文件并确认回执后才移除记录；清理失败时保留记录并提示稍后重试。运行中或尚未完成结果通知的任务不能删除。删除不可恢复；成功后移除该行，当前页为空时返回有效页。

### 组合过滤与复制进度

复制和监听表单支持简单关键词或组合表达式，后者可填写 `msgre:舞团&(king8|k8)`。保留原有文本测试，表达式错误不会创建任务。复制任务显示检索命中数、实际复制进度和成功/失败结果；检索阶段无百分比。任务标题包含来源、完整过滤条件、目标及可选 `Topic:名称(id)`，无 Topic 时不显示该后缀。任务取消和记录删除的边界不变。
